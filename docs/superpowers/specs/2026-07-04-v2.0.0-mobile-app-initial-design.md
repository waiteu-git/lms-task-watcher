- **朝まとめ（無料ユーザー分）はサーバープッシュではなくローカル通知で実装する**。理由は本書2章末。上位方針の「無料=朝まとめ1日1回」の体験は維持し、実装面のみアカウントレス設計に合わせて変更する。

先行設計書 `2026-06-28-mobile-app-design.md` は上位方針で大部分が上書き済み。本書がそれに代わる v2.0.0 の正となる。Expo Push・APIの口という基盤アイデアのみ引き継ぐ。

## 初版スコープ（最小コア）

「課題通知＋時間割閲覧＋見張り番プッシュ」に最小化する（上位方針6章）。

**含む:**

- LETUS課題の自動収集（アプリ内）
- CLASS時間割の閲覧（アプリ内収集）
- 課題一覧表示・提出状態表示
- 期限前ローカル通知（無料）／朝まとめ（無料=ローカル、サブスク=サーバー）
- 見張り番プッシュ（サブスク）

**含まない（v2.0.x へ後送り、確定済み）:**

- 手動課題追加、優先度・メモ編集
- 拡張↔アプリ同期
- ホーム画面ウィジェット、スヌーズ、統計
- カスタム通知ルール（設計は別書、モバイル移植はv2.0.x）

## セクション1: 全体アーキテクチャ

```
[モバイルアプリ（React Native / Expo managed・TypeScript）]
  ├── 収集レイヤー（ハイブリッド）
  │     ├── LETUS: WebViewのSSOセッションCookie → 直接fetch＋HTMLパース（拡張ロジックのTS移植）
  │     └── CLASS: 非表示WebView＋JS注入でDOMパース（JSFポストバックはブラウザに任せる）
  ├── ローカルDB（expo-sqlite: 課題・時間割・設定）
  ├── ローカル通知（expo-notifications: 期限前通知＋朝まとめを予約）
  └── サブスクのみ: サーバー同期＋Expo Pushトークン登録
        ↕ HTTPS
[ラズパイAPIサーバー（既存 api/ を拡張）]
  ├── JWT認証・Stripe（既存流用）
  ├── 課題状態の受信（見張り番用、サブスクのみ）
  └── 見張り番スケジューラ → Expo Push API（24h→6h→1h、未提出のみ、提出同期で停止）
```

### 設計原則

- **無料ユーザーはアカウントレスで全コア機能が動く**（収集・一覧・時間割・ローカル通知・朝まとめ）。サーバーに一切データを送らない
- **サブスクだけがログインし課題状態をサーバーへ同期**（見張り番の前提データ）
- 認証情報は端末内のみ（Orario教訓）。サーバーが預かるのは課題メタデータとプッシュトークンのみ
- 課題期限は「事前に分かっている未来の日時」。常時スクレイピング不要。起動時に収集→ローカル通知を予約すればiOSバックグラウンド制約下でも通知は確実に鳴る（上位方針4章）

## セクション2: 収集レイヤー（ハイブリッド方式）

| ソース | 方式 | 頻度 |
|---|---|---|
| LETUS（Moodle） | WebViewのSSOセッションCookieを用いたfetch＋HTMLパース。`public/background.js`の収集ロジックをTypeScriptへ移植 | アプリ起動時＋手動更新 |
| CLASS（UNIPA/JSF） | 非表示WebViewでメニュー遷移をJS駆動→`table.classTable`をパース（付録Aのセレクタ） | 手動更新＋学期切替時のみ |

- セッション切れ時のみログインWebViewを表示。SSO画面に直接入力し、WebViewのCookie永続化で以後は自動通過を狙う（体験は要実測）
- CLASSは**履修科目・時間割・時限時刻表のみ**取得。成績・掲示等は恒久除外（プライバシー・大学関係リスク）
- LETUSとCLASSはセッション/SSO挙動が別物。個別に実測する
- CLASSは低頻度収集で十分（時間割は学期内で不変）。毎起動スクレイプはしない

### 朝まとめをローカル通知にする理由

無料ユーザーはアカウントレス（サーバーは無料ユーザーの課題を知らない）ため、朝まとめをサーバープッシュで送れない。よってアプリ起動ごとに、ローカルDBの既知課題から翌朝以降・数日分の朝まとめ通知を`expo-notifications`で再予約する。前日にアプリを開いていれば内容は正確、開いていなくても既知データで概ね正確。サブスクは見張り番と同経路のサーバープッシュで常に最新の朝まとめを受け取る。

## セクション3: 通知設計（初版）

| 通知 | 無料 | サブスク | 実装 |
|---|---|---|---|
| 期限前ローカル通知（24h/3h/1h） | ✅ | ✅ | 収集成功時に`expo-notifications`で予約し直し |
| 朝まとめ（1日1回） | ✅ ローカル | ✅ サーバープッシュ | セクション2末を参照 |
| 見張り番（24h→6h→1h、未提出のみ・提出検知で停止） | — | ✅ | サーバーcronがExpo Push API呼び出し |

- しきい値は既存拡張の1h/3h/24hに揃える（無料ベースラインの一貫性）
- 見張り番が看板有料機能。機能差が体験として一瞬で分かることを優先

## セクション4: サーバーAPI拡張（既存 api/ に追加）

| メソッド | パス | 用途 | 認可 |
|---|---|---|---|
| POST | `/api/devices/token` | Expoプッシュトークン登録 | 要JWT |
| PUT | `/api/v2/assignments/state` | アプリからの課題状態同期（見張り番の判定材料） | 要JWT＋サブスク有効 |

- 見張り番スケジューラ（node-cron）: 期限接近×未提出をチェックしてExpo Push、提出済み同期で自動停止
- JWT認証・Stripeサブスク判定は既存基盤を再利用
- 旧設計の優先度/メモ用API・サブスクゲートは実装しない（初版スコープ外・上位方針で廃止済み）
- ラズパイ変更後は `pm2 restart` までセットで行う（デプロイ手順の既定ルール）

## セクション5: 画面構成（初版・4画面）

| 画面 | 内容 |
|---|---|
| 課題一覧（ホーム） | 期限順ソート、提出状態バッジ。タップでLETUS該当ページをWebView表示 |
| 時間割 | 学期グリッド表示（今日を強調）。付録Aの時限時刻表を使用。学期切替（前期/後期）セレクタ |
| 設定 | 通知オン/オフ、手動更新、サブスクログイン、購入はWeb（lms.waiteu.dev）へ誘導 |
| 収集/ログインWebView | 通常は非表示。セッション切れ時のみ表示 |

購入導線はWebのみ（AppleのIAP手数料回避、スマホ新法の外部決済誘導を利用）。アプリは購入状態を反映するだけ。

## セクション6: プロジェクト構成・技術選定

- モノレポ `app/` ディレクトリに配置（`api/`・`landing/` と同格）。API変更とアプリ変更を同一ブランチ・同一worktreeで扱い、docs仕様も一元管理
- Expo managed workflow、TypeScript。ネイティブ機能が必要になった時のみベアへ移行
- ローカルDB: `expo-sqlite`。通知: `expo-notifications`。収集WebView: `react-native-webview`
- テスト中心: LETUS/CLASSパーサー（HTMLフィクスチャ）、通知予約ロジック、朝まとめ再予約ロジックのユニットテスト
- ブランド名（正式名称）はストア申請前に決定するタスクとして実装計画に明記。設計・コードはコード名で続行

## セクション8: 要検証事項（実装セッション冒頭で実施）

1. LETUS/大学SSOのCookie寿命の実測（WebView再ログイン体験の確認）
2. モバイルUAでCLASSがスマホ版へ誘導される場合の挙動 → PC版UA固定 or スマホ版パーサーのどちらに倒すか決定

4. ラズパイの無料アカウント数百件時の負荷（※初版は無料=アカウントレスのため、実質サブスク件数依存に縮小）

## 付録A: CLASS 時間割ページ 実地調査結果（2026-07-04）

Chrome拡張ブラウザ経由で実際にログインし取得した構造。パーサー設計の一次情報。

### 到達フロー

1. `https://class.admin.tus.ac.jp/` → ENTER → SSO（既ログインならセッション通過）
2. グローバルメニュー「履修」→「学生時間割表」
3. 遷移先: `https://class.admin.tus.ac.jp/uprx/up/xu/xut124/Xut12401.xhtml`（機能ID `Kmd008` / 表示上は `学生時間割表[Kmd008]`）
4. フォーム`action`は全て `/uprx/up/km/kmd008/Kmd00801.xhtml`（JSF、`javax.faces.ViewState`あり）

### 時間割グリッド構造

- テーブル: `table.table.table-bordered.classTable`（9行×7列）
- ヘッダー行: `["", "月曜日", "火曜日", "水曜日", "木曜日", "金曜日", "土曜日"]`
- 行ラベル（1列目）: `1, 2, (昼休み), 3, 4, 5, 6, 7`（3行目は「昼休み」ダミー行）
- 各授業セル: `div.jugyo-info.jugyo-normal` を内包。1セルに複数コマ（連続コマ）が入る場合あり
- セル内の子`div`（上から）:
  - `div.fontB` — 科目名（例「基礎電気数学及び演習 （１組）」）
  - `div` — 担当教員（例「王　宇凱」）
  - `div > span` — 教室（例「野：445教室」／遠隔は「遠隔（オンライン）」）
  - `div` — 科目コード（例「9973337」、LETUS課題との突合キー候補）
  - `div.taniSu` — 単位数（例「2.0単位」）
  - `div.sign.signClass` — バッジ（例「複数回」）※任意

### 時限時刻表

`dd.jigenArea` 内テキスト（野田キャンパス）:

```
1限 08:50～10:20 / 2限 10:30～12:00 / 3限 13:00～14:30 / 4限 14:40～16:10 /
5限 16:20～17:50 / 6限 18:10～19:40 / 7限 19:50～21:20
```

- キャンパスにより時刻が異なる可能性あり。`dd.jigenArea`のテキストをパースして時限→時刻を得る方針（ハードコードしない）

### 学期切替

- セレクタ `select#funcForm:gakki_input`（options: すべて対象/前期/後期、value: ""/1/2）
- キャンパス絞り込み `select#funcForm:campusNo_input`（神楽坂各種/野田等）
- 表示ボタン `button#funcForm:search`
- 検証: `gakki_input`を「後期」(value=2)にして`search`クリック→後期時間割（現代物理学・電気磁気学等）に切替を確認。前期へ復元済み

### パーサー突合キー

- 科目コード（例`9973337`）が時間割セル・LETUS課題・履修アンケート一覧で共通。LETUS課題⇔時間割コマの突合キーとして有力
