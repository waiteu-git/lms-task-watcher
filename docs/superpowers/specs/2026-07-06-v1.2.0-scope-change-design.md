## 背景

- 旧 v1.2.0（free-first 版）は「entitlement無料開放＋パス型決済（半期¥720・年¥1,200）＋Phase C申請」だった。
- ロードマップ改定（2026-07-06）でフェーズ2をCLASS連携（アプリ実装に先立ち実装）に前倒しした。CLASS連携は `class.admin.tus.ac.jp` の `host_permissions` 追加を伴い、**どのみち Chrome Web Store 再審査になる**。
- ならば無料開放と同じ再審査の機会にCLASS連携を載せた方が、審査回数・ユーザー体験の分断が少ない。パス型決済は審査に必須ではなく、実装・Stripe調査コストがかかる。

## 決定

### v1.2.0 スコープ（4本立て）

1. **entitlement変更（無料開放）**: メモ・優先度・テーマのサブスクゲート撤去。`docs/superpowers/specs/2026-07-04-free-first-entitlement-design.md` / `plans/2026-07-04-free-first-entitlement.md` の通り。バックエンド変更なし。
2. **CLASS連携**: CLASS時間割の収集＋ダッシュボードのグリッド表示＋科目連携（課題↔時間割の自動ひも付け）。突合キーは CLASS 7桁科目コード ↔ LETUSコース名埋込コード。
3. **シラバス埋め込み表示**: CLASSの静的HTMLシラバス（`slResult/{年度}/japanese/syllabusHtml/SyllabusHtml.{年度}.{7桁コード}.html`）を fetch し、拡張内（科目ハブ）にパース・整形表示。
4. **コース内容の更新通知**: 定義A＝`/mod/*/view.php`（教材/課題/アクティビティ）リンクの増減のみ。コースごとにリンク集合をスナップショットし、再スキャン時に差分検知してバッジ・通知。ページ全体ハッシュ差分は誤検知が多く不採用。

### 課金区分

- **v1.2.0の4機能はすべて無料開放**。CLASS連携・シラバス・更新通知に課金ゲートを設けない。
- **サブスク有料化の検討自体を、リタス初版公開（2026年9月）まで凍結**する。この期間はマネタイズを考えず、無料でのユーザー獲得（ファネル最大化）に振る。月額¥120サブスク（既存の同期・カスタム通知ルール・Discord等）は既存契約者向けに現状維持するが、v1.2.0で新たな有料機能は追加しない。

### スコープから外すもの

- **パス型決済（半期¥720・年¥1,200）**: バージョン未割当のバックログへ。上記の通り**リタス初版公開後まで検討しない**。free-first スペックの決済記述は本決定で凍結。
- `/api/timetable`・時間割のクロスデバイス同期: v1.2.0では実装しない（ローカルのみ）。リタス公開後の課題。

### データ・権限・リリース

- 保存は `chrome.storage.local` のみ。**バックエンド変更なし**（ラズパイのデプロイ不要）。
- `manifest.json` の `host_permissions` に `https://class.admin.tus.ac.jp/*` を追加。時間割収集（Content Script）とシラバスHTMLの fetch の両方で必要。
- 収集は既存の Content Script 方式を踏襲（ユーザーがCLASS/LETUSページを開いたときに取得、常駐スクレイピングやバックグラウンド巡回はしない）。
- 上記4本を **v1.2.0として一括で Phase C（Chrome Web Store申請）** に載せる。

## コード流通の規約（拡張 → リタス 逆流）

拡張とリタスは分離済み（2026-07-06）だが、LETUS/CLASSの**純粋ロジック**（HTMLパーサ・差分・シラバスURL生成・学年暦）を共有する。共有パッケージ化はせず、**拡張をイテレーション面**として磨き、安定版を litas へ逆流させる。

- **正の源**: これらの純粋ロジックは、ブラウザ実DOMでのデバッグが容易な**拡張側で先に詰める**。
- **突き合わせて寄せる**: litas には既存実装があるため、**単純上書きせず両者を突き合わせて良い方に寄せる**。挙動差があれば handover に記録。
- **逆流の手順**: 拡張側で純粋ロジックを変更したら、同じ変更を litas の対応ファイルへ反映し、`litas` の `pnpm test` が通ることを確認する。取りこぼし防止のため、変更時は WORKLOG（拡張）と handover（litas）の双方に「逆流済み/未」を記録する。
- **逆流の対象は純粋ロジックのみ**。UI（React DOM vs React Native）・ストレージ（chrome.storage.local vs AsyncStorage）・収集経路（Content Script vs WebView注入）は各リポジトリ固有で、逆流しない。

| ロジック | 拡張（lms-task-watcher）想定パス | litas 既存パス |
|---|---|---|

注: 拡張側の新規パスは実装フェーズで確定してよい（表は移植の起点を示すもの）。`letusLinks` は元々「拡張 → litas」に移植された経緯があり、逆流時は起源が拡張側である点に注意。
