## B. 時間割UIの3改善

現状: 時間割グリッドはダッシュボード限定（`src/components/TimetableSection.tsx`）。セルは全課題の単純件数を `課題{count}` で表示（`src/core/timetableLink.ts` の `courseCodeCounts` は締切・提出状況を問わず計上）。コース更新は `src/components/CourseUpdatesSection.tsx` がダッシュボードに一覧表示するのみ。ポップアップに時間割は無い。

### B-1. ポップアップに「今日の時間割」を常設

**目的**: 拡張機能を開いた瞬間に今日の授業と課題の緊急度が分かる。ダッシュボードを開かずに済む。

- 新規コンポーネント `TodayTimetable`（`src/components/TodayTimetable.tsx`）。ポップアップ（`!isDashboard`）の `miniSummary` の下に配置する。
- 中身: **今日のコマを時限順（1限→）の縦リスト**。各行に「時限・科目名・教室・緊急度ドット（B-2）・NEWバッジ（B-3）」。
- 週末（土日）や今日が授業ゼロの日: **翌月曜**を表示し「（月曜の予定）」等のラベルを添える。翌月曜も授業が無い場合は「本日は授業なし」。
- 曜日判定は `TimetableSection` と同じ `JS_DAY_TO_DOW` を共有ユーティリティ化して再利用する（`src/core/timetableView.ts` に `resolveDisplayDay(now)` を追加。土日→翌月曜のロジックもここに集約）。
- 時間割未取得（`rawHtml === null`）のときは、CLASSで時間割を開くよう促す1行の案内（`TimetableSection` の空表示と同文言）。
- **ポップアップの拡大**: `App.css` のポップアップ幅/`body` 幅を現状から約40〜60px広げ、`TodayTimetable` が窮屈にならない高さにする（数値は実装時に実測で微調整）。ダッシュボードのレイアウトには影響させない。

### B-2. 課題バッジを件数から緊急度カラーへ

**目的**: 「いくつあるか」ではなく「どれだけ急ぎか」を一目で示す。

- セルの `課題{count}` 表示（`TimetableSection.tsx` の `timetableCount`）を廃止し、**緊急度ドット**に置き換える。同じドットをポップアップの `TodayTimetable`（B-1）にも表示する。
- 判定対象: そのコマの科目コードに紐づく課題のうち、**未提出**かつ **`lifecycleStatus !== 'passed'`**（期限切れ除外）かつ **`before_start` 除外**のもの。
- **手動追加課題も含める**（ユーザー指示）: `deadline` を持ち **`submitted === false`** の手動課題を対象に加える。時間割コマへの突合は `extractCourseCodes(manualAssignment.courseName)`（LETUSコース名の埋込7桁コード。scan課題と同じキー）で行う。科目コードを持たない手動課題（自由入力のコース名など、7桁コードを含まないもの）は時間割コマに紐づかないため、緊急度ドットには寄与しない（ダッシュボードのタイムラインには従来どおり出る）。
- ドットの色（対象課題の**最も近い締切**で決定）:
  - **当日中（締切が本日中 = カレンダー上の今日の終わりまで）→ 赤ドット**
  - **1週間以内（今日を除き7日以内）→ 橙ドット**
  - それ以外・対象なし → **無印**（ドットを出さない）
- 「当日中」「1週間以内」の閾値は `src/utils/date.ts` に純粋関数として追加（例 `isDueToday(deadline, now)`／`isDueWithinDays(deadline, now, days)`。カレンダー日基準。テスト同梱）。
- `linkAssignmentsToSlots`（`src/core/timetableLink.ts`）を拡張し、scan課題に加えて**手動課題も引数で受け取り**、`courseCodeCounts`（件数）に代えて/加えて **`courseCodeUrgency: Record<string, 'today' | 'week' | 'none'>`** を返す。件数計算の既存呼び出し元が無くなるなら `courseCodeCounts` は削除。緊急度は科目コード単位で「最も近い締切のtier」を採る（scan課題・手動課題を合算して最短締切を評価）。統合コース（複数コード）は各コードのコマに同じ判定を反映。
- アクセシビリティ: ドットに `title`/`aria-label`（「当日提出あり」「今週提出あり」）を付ける。色のみに依存しない。

### B-3. コース更新の NEW バッジを時間割に表示

**目的**: コース内容の更新（定義A = `/mod/*/view.php` の増加）を、通知・ダッシュボード一覧に加えて時間割上でも視認できるようにする。

- 未読更新の有無を科目コード単位で判定する。`src/background/courseUpdatesStore.ts` の `getUnreadUpdates(courseId)` はコースID単位なので、`courseId → 未読件数>0` を求め、`extractCourseCodes(course.name)` で科目コードへ写像して「未読ありコード集合」を作る。
- 時間割セル／今日リストの行で、そのコマの科目コードが未読集合に含まれれば **「NEW」バッジ**を表示する。緊急度ドット（B-2）とは別枠で共存させる。
- 既読化でバッジは消える。既読は既存フロー（`CourseUpdatesSection` の項目クリック `markUpdateRead` / 「全既読」`clearCourseUpdates`）に委ねる。時間割のNEWバッジ自体はクリックで既読化しない（表示のみ。将来クリック導線が要れば別タスク）。
- 未読集合の算出は `App.tsx` 側で行い、`TimetableSection`／`TodayTimetable` に props で渡す（両者が同じデータを使えるように）。`CourseUpdatesSection` と算出が重複するが、参照する `chrome.storage.local` は同一なので実害なし。将来共通フック化を検討。

## C. オンボーディング刷新

### C-1. ウェルカムガイド（既存実装の改訂）

**現状（develop で実装済み）**: `public/welcome.html` + `public/welcome.js`、`src/background/index.ts` の `handleInstalled`（`WELCOME_GUIDE_SHOWN_KEY` で新規時＝welcome、既存ユーザーは次回更新で一度だけwelcome、以降changelog）、Chrome/Edge出し分けは**すでに動いている**。onInstalled機構・フラグは触らない。**welcome.html の本文（ステップ文言）だけを差し替える**。

現行welcome.htmlの問題点:
- ②「使い始めの3ステップ」が旧フロー（LETUS開く→ダッシュボードで手動選択→更新）で、自動選択（C-2）・CLASS先行と矛盾する。
- ①末尾のnote「ツールバーの拡張機能アイコンから残り課題数がひと目でわかります」は**実態と不一致**（ツールバーの課題数バッジは未実装＝`setBadgeText`未使用）。ポップアップに今日の時間割・緊急度が出る旨（B-1）に書き換える。

改訂後のステップ（コース自動選択が成立する順序にする）:

1. **拡張機能をツールバーに固定**（既存設計どおり。🧩→📌）
2. **CLASSで時間割を取り込む** — CLASSにログイン →「履修 → 学生時間割表」を開くと今学期の時間割を自動取得。
3. **LETUSでコースを開く** — LETUSにログインしてコースページを開くと、コースを自動登録し、**時間割にある科目を自動でON**（C-2）。手動での取捨選択も可能。
4. **「今すぐ更新」で課題を取得** — 以降は自動更新。

既存設計の旧②「ダッシュボードで追跡するコースを手動選択」ステップは、自動選択（C-2）に置き換わるため削除する。通知の仕組み・リタス事前登録導線・changelogリンクは既存設計どおり残す。ポップアップ側 `OnboardingBanner` の文言も、この新フロー（CLASS先行・自動選択）に合わせて見直す。

### C-2. コース自動選択（時間割準拠）

**目的**: v1.1.0のコース選択を土台に、ユーザーの手動選択負担をなくす。時間割に載っている＝今学期履修中の科目だけを追跡対象にする。

**判定ルール**:
- 対象コースの `extractCourseCodes(course.name)`（複数可）と、取得済み時間割の科目コード集合を突合する。
- **いずれか1つでも一致すれば自動ON**（統合コース対応。ユーザー指示: 片方一致で選択）。
- 時間割に無いコード（過去学期・サンプル科目等）のみのコースは自動ONしない。

**手動トグルの尊重**:
- ユーザーが明示的にトグルした科目は自動選択で上書きしない（ONにした/OFFにしたの両方向を尊重）。
- 実装: `Course` に選択の出所を持たせる。案として `autoSelected?: boolean`（自動でONにした印）と、ユーザー操作を記録する `userToggled?: boolean` を追加する。`App.tsx` の `toggleCourse`／`setAllCoursesEnabled` が呼ばれたら `userToggled: true` を立てる。自動選択は **`userToggled` が立っていないコースだけ**を対象に enabled を更新する。
- 型追加は `src/core/types.ts` の `Course` に後方互換（optional）で行う。既存保存データは `undefined` 扱いで従来通り動く。

**発火タイミング（両順序に対応）**:
- **LETUSコース検出時**（`UPSERT_COURSES` → `upsertCourses`、`src/background/index.ts`）: 新規/既存コースについて、時間割取得済みなら一致するものを自動ON（`userToggled` 未設定のみ）。
- **CLASS時間割取得時**（`src/content/classTimetable.ts` の保存を受けた background 側の処理、または保存直後のフック）: 既存の全コースを再評価し、一致かつ `userToggled` 未設定のものを遡って自動ON。
- 自動選択ロジックは純粋関数 `selectCoursesByTimetable(courses, timetableCodes): Course[]`（`src/core/` に新規、テスト同梱）に切り出し、background の2箇所から呼ぶ。副作用（storage保存）は呼び出し側。

**科目コードの取り出し**: 時間割HTMLから科目コード集合を得るヘルパを用意する（`parseTimetable(rawHtml)` の slots → `classes[].courseCode` の集合。空文字は除外）。`src/core/timetableStore.ts` か `timetableView.ts` に `getCapturedCourseCodes(year, semester)` として追加。

1. **changelog書き換え**: `public/changelog.html` の「今回の変更点」をv1.2.0内容（無料開放・CLASS連携・シラバス・更新通知・時間割UI改善・自動選択・ウェルカムガイド）へ、見出しを「v1.2.0にアップデート」に。リタス事前登録導線を必ず掲載（CLAUDE.mdルール）。
2. **純粋ロジックのlitus逆流**: timetable/syllabus/courseUpdates の純粋層を `C:\dev\litus` の対応ファイルへ反映し `litus` の `pnpm test` 緑を確認。単純上書きせず突き合わせ、WORKLOG（拡張）とhandover（litus）に逆流済み/未を記録。※今回追加の `selectCoursesByTimetable`・緊急度算定は拡張発の新規ロジックなので、litus側に相当機能があれば同様に突き合わせる。
3. **バージョン確定**: `manifest.json` の `version` を `1.2.0` に。`store-listing.md` 等の版数表記も揃える。
4. **品質ゲート**: `pnpm vitest run src`（新規テスト含め緑）・`pnpm lint`・`pnpm build`（`tsc -b && vite build`）がすべて通ること。`dist/` は生成物なので直接編集しない。
5. **手動疎通**: 実CLASS/LETUS環境で、ウェルカムフロー（固定→CLASS時間割→LETUS自動選択→更新）、緊急度ドット、NEWバッジ、ポップアップ今日の時間割を確認（実装済み≠検証済みの原則）。
6. **ブランチ運用**: 作業は `develop`（v1.2.0系）に集約 → 品質ゲート通過後 `main` へマージ。安全判定復帰後にgitで未マージの改善ブランチ状況を洗い出し、v1.2.0に含めるべきものを確認する（現時点では本書スコープの範囲に限定。litus-devlog/letus-api-deadline等の別軸ブランチは対象外）。
7. **Chrome Web Store申請（Phase C）**: `host_permissions` に `class.admin.tus.ac.jp` 追加済みを確認のうえ、4機能＋本書の改善を一括申請。
