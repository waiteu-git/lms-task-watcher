# v1.2.0 No.4 コース内容の更新通知（定義A）— 設計

作成: 2026-07-07
種別: 機能設計（brainstorming成果）

## この文書の位置づけ

`docs/superpowers/specs/2026-07-06-v1.2.0-scope-change-design.md` の No.4「コース内容の更新通知（定義A）」の詳細設計。定義A＝コースページの `/mod/*/view.php`（教材・課題・アクティビティ）リンク集合の増減をスナップショット差分で検知する。ページ全体ハッシュ差分は誤検知が多く不採用。

## 決定（確定した選択）

- **検知範囲**: **追加のみ通知**。スナップショットは常に全集合（`/mod/*/view.php`）を保存し、削除はスナップショットを更新するが通知しない。
- **表示面**: **Chrome通知** ＋ **ダッシュボードの項目履歴リスト**（未読数・クリックで開いて既読化）。ツールバーのアイコンバッジは使わない。
- **シグネチャ範囲**: 全 `/mod/[^/]+/view.php`（教材=resource/folder/page/url/book 等を含む。課題限定ではない）。`/mod/label` は view.php を持たず自然に除外。
- **初回スキャン**: 前回スナップショットが無いコースは**ベースライン保存のみ・通知なし**（全項目が「新規」扱いになるのを防ぐ）。
- **通知粒度**: 追加のあった**コースごとに1本**（複数コース更新時もコース単位）。「○○ に新しい教材/課題 N件」。クリックでダッシュボードを開く。
- **検知フック**: 既存 `scanAssignmentCandidatesInBackground`（`src/background/index.ts`）内。コースHTMLは既に `fetch(course.url)` 済み。**追加のfetchなし**。
- **manifest・バックエンド変更なし。**

## アーキテクチャ（ユニット）

### 1. `src/core/letusLinks.ts`（共有・`index.ts` から抽出）

既存の `extractLinksFromHtml(html, baseUrl): CourseLink[]`（`src/background/index.ts` 内、正規表現ベース）と依存ヘルパ `stripTags`・`decodeHtmlEntities` をこのモジュールへ移して `export` する。`index.ts` は import に切り替える（**挙動不変のリファクタ**）。litus `src/parsers/letusLinks.ts` に対応。

```ts
export type CourseLink = { url: string; title: string }
export function stripTags(html: string): string
export function decodeHtmlEntities(text: string): string
export function extractLinksFromHtml(html: string, baseUrl: string): CourseLink[]
```

- 注: `index.ts` の `htmlToPlainText` は `stripTags`/`decodeHtmlEntities` に依存するため、これらを `letusLinks.ts` から import する（重複させない）。`normalizeText` 等その他のヘルパは `index.ts` に残す。
- これが設計書の言う「拡張の既存リンク抽出（`index.ts`、litus移植の起源）との突き合わせ」。

### 2. `src/core/courseUpdates.ts`（純関数・litusから移植）

litus `src/updates/courseUpdates.ts` と対応（突き合わせて良い方に寄せる）。

```ts
import { extractLinksFromHtml, type CourseLink } from './letusLinks'

const MOD_VIEW = /\/mod\/[^/]+\/view\.php/

/** コースHTMLから /mod/*/view.php リンク集合を url 昇順・重複排除で取り出す（シグネチャ）。 */
export function computeCourseSignature(html: string, baseUrl: string): CourseLink[]

/** 前回→今回の url 集合差分。 */
export function diffCourseSignature(prev: CourseLink[], next: CourseLink[]): { added: CourseLink[]; removed: CourseLink[] }
```

- `computeCourseSignature`: `extractLinksFromHtml` → `MOD_VIEW.test(url)` で絞り → url で重複排除 → url 昇順ソート。
- `diffCourseSignature`: `prev`/`next` の url 集合で added（next のみ）/removed（prev のみ）。

### 3. `src/background/courseUpdatesStore.ts`（I/O）

```ts
export type UnreadUpdate = { url: string; title: string; detectedAt: string }
export function getCourseSignature(courseId: string): Promise<CourseLink[] | null>
export function saveCourseSignature(courseId: string, sig: CourseLink[]): Promise<void>
export function getUnreadUpdates(courseId: string): Promise<UnreadUpdate[]>
export function addUnreadUpdates(courseId: string, items: UnreadUpdate[]): Promise<void>
export function markUpdateRead(courseId: string, url: string): Promise<void>
export function clearCourseUpdates(courseId: string): Promise<void>
```

- キー: シグネチャ=`courseSignature:{courseId}`（`CourseLink[]`）、未読=`courseUpdates:{courseId}`（`UnreadUpdate[]`）。
- `addUnreadUpdates`: 既存未読に url 重複を避けて追記。

### 4. 検知フック（`scanAssignmentCandidatesInBackground` 内）

各コースの HTML 取得直後に（純関数に寄せた）`processCourseUpdate` を呼ぶ。テスト可能な純ロジックとして切り出す:

```ts
// src/core/courseUpdates.ts に併置（純関数）
export function computeCourseUpdate(
  prevSignature: CourseLink[] | null,
  html: string,
  baseUrl: string,
  now: string,
): { signature: CourseLink[]; added: UnreadUpdate[]; skipSave: boolean }
```

- `prevSignature === null`（初回）: `{ signature: computeCourseSignature(...), added: [], skipSave: false }`（ベースラインのみ保存）。
- 新signatureが空 かつ 前回が非空: `{ signature: [], added: [], skipSave: true }`（ログイン切れ等の一時0件でベースラインを壊さない）。
- それ以外: `added = diffCourseSignature(prev, sig).added` を `UnreadUpdate`（`detectedAt=now`）へ写像、`skipSave: false`。
- 呼び出し側（index.ts）: `skipSave` が false のとき `saveCourseSignature`。`added` があれば `addUnreadUpdates` ＋ コース単位通知。fetch失敗コースはそもそも呼ばずスキップ。

### 5. 通知（`createNotification` 基盤）

追加のあったコースごとに `createNotification({ title: 'コース更新', message: '○○ に新しい教材/課題 N件' , ... })`。クリックでダッシュボード（`index.html#dashboard`）を開く。既存の `notificationTargets` 機構に合わせる。

### 6. ダッシュボードUI `src/components/CourseUpdatesSection.tsx`

- 未読のあるコースを、コース名＋追加項目のリンク付きリスト（タイトル＋検知日時）で表示。
- 項目クリック → `chrome.tabs.create({url})` で LETUS を開き、その項目を `markUpdateRead`。
- コースごとに「全既読」、セクション見出しに未読合計バッジ。
- 未読ゼロなら非表示。ダッシュボードのサマリ付近（時間割セクションの近く）に配置。

## データフロー

scan（既存fetch）→ `computeCourseUpdate`（前回signatureとdiff）→ 未読追加＆Chrome通知 → 新signature保存。
ダッシュ: `courseUpdates:*` を読み表示 → 項目クリックで既読化・LETUSを開く。

## エラー処理

- fetch失敗コース: `computeCourseUpdate` を呼ばずスキップ（signatureを更新しない、次回再評価）。
- パース0件: 例外にしない。一時的な0件（ログイン切れ等）でベースラインを壊さないよう `computeCourseUpdate` の `skipSave`（新signature空 かつ 前回非空）で保存を止める。

## テスト

- `letusLinks.test.ts`: `extractLinksFromHtml`（相対URL解決・タグ除去・エンティティ復号）。既存 `index.test.ts` の挙動が保たれること（リファクタ後も既存テスト緑）。
- `courseUpdates.test.ts`: `computeCourseSignature`（mod/view絞り・重複排除・ソート・非modリンク除外）、`diffCourseSignature`（added/removed）、`computeCourseUpdate`（初回=added空・2回目=差分・空signatureガード）。
- `courseUpdatesStore.test.ts`: chrome スタブで signature/未読の保存・既読化。
- UI（`CourseUpdatesSection`）は手動確認。

## 権限・リリース・逆流

- **manifest変更なし**（`letus.ed.tus.ac.jp` は既存）。バックエンド変更なし。
- `courseUpdates` は litus `src/updates/courseUpdates.ts` の双子。移植時に突き合わせて良い方に寄せ、handover/WORKLOG に逆流状態を記録。
- `letusLinks` は拡張発（litusへ移植された起源）。共有化後の差分があれば litus 側へ反映。

## 非目標

- ページ全体ハッシュ差分・本文変更検知（定義B以降）。定義Aのリンク集合増減のみ。
- 削除の通知（スナップショットは更新するが通知しない）。
- 更新項目のクロスデバイス同期（ローカルのみ）。
- 通知のカスタムルール連携（既存のサブスク機能とは独立）。
