# 締切スキャン精度向上・未取得削減 設計

- 日付: 2026-07-04
- 対象: 締切パース（`src/background/index.ts`）／ログイン検知
- 起点: 本番 v1.0.4 で報告された「閉じた小テストの締切が今日の日付に化ける」バグ。テスターの診断データ（85件）で原因を確定し、精度向上・未取得削減へ拡張。

## 背景・確定した原因

診断ビルド（v1.0.5ベース）でテスターの実LETUSページを85件キャプチャし解析した結果、2つの欠陥を確定した。

1. **本来の締切ラベルがキーワード未登録**: Moodleは締切超過で小テストの表示を「終了予定 → 終了済み」に変える。`deadlineKeywords` に `終了予定` はあるが `終了済み` が無いため、閉じた小テストは自分の締切フィールド（例: 本文冒頭の `終了済み: 2026年 06月 19日(金曜日) 23:59`）を拾えない。
2. **ページ全文を解析対象にしているためナビ/タイトルを誤爬取**: 自分の締切を拾えないまま、ページ後方のナビに並ぶ別アクティビティ名「第13回小テスト（**締切**：7月3日）」の `締切` を最初にヒットして `7月3日`（年なし→今年・時刻なし→23:59）を採用し、`2026-07-03 23:59` に化ける。

課題(assign)が正常なのは締切ラベルが `期限:`（登録済み）で本文の早い位置に出るため。受付中の小テストが正常なのは `終了予定:`（登録済み）が出るため。**閉じた小テストだけが壊れる**理由がこれで全て説明できる。

### 診断データで見えた未取得（deadline=null 18件）の内訳

- quiz 11件: 大半は `開始日時` のみで締切なし＝**nullが正しい**常時開放小テスト。`終了済み` を持つものだけ回復対象。
- assign「締切（5/29 14:40) 課題」: `期限`/`締切` ラベルがあるのに null。原因は (a) ページタイトルの `締切` を拾い、(b) `5/29` スラッシュ表記が現行の `M月D日` 正規表現で解析不能。本来の `期限` フィールドは本文の後方に存在。
- feedback/choice: 締切なし（正しいnull）か、`終了済み` 持ちで回復対象。

## 方針

**基本スタンス: バランス。** 誤った締切を出すことは「期限なし」表示より悪い、を原則とし、精度向上（本文限定・ラベル拡充）を主軸に、推定（スラッシュ・タイトル）は誤検知を抑えつつ限定採用する。

## 設計詳細

### ① 締切ラベル拡充（v1.0.6 + develop）

- `extractDeadlineText` の `deadlineKeywords` に **`終了済み`** を追加。
- `startKeywords` に **`開始済み`** を追加（`開始` で既にカバーされるが整合のため明示）。
- キーワード選択は「最早出現位置」方式のため、`終了済み`（本文冒頭）が後方のナビ `締切` より前に来て正しく採用される。
- 実データ検証済み: 小試験→6/19、小テスト第9回→6/5、第12回→6/26 に回復、正常5件は不変。

### ⑤ ログイン検知修正（v1.0.6 + develop）

- 現状: `checkIsLoggedIn` は未ログイン時、LETUS が外部SSO/別ドメインへリダイレクト→`fetch` が例外→`catch` で `network_error` を返し「通信エラー」表示になる。
- 修正: 判定順を以下に変更。
  1. `fetch(course.url, { credentials: 'include', redirect: 'manual' })` で叩く。
  2. `response.type === 'opaqueredirect'`（クロスオリジンのリダイレクト）→ `login_required`。
  3. 追跡できた場合、`response.url` が letus オリジン外／`/login/` を含む → `login_required`。
  4. `response.ok` かつ本文が未ログイン文言（`あなたはログインしていません`/`You are not logged in`）→ `login_required`。
  5. 上記以外の `!response.ok` や `fetch` 例外 → `network_error`（真のネット障害のみ）。
- 手動更新・自動スキャン両経路が同関数を使うため一括で是正される。

### ② 本文限定抽出（develop）

- `htmlToPlainText` の前段に `extractMainRegion(html)` を追加。Moodle Boost テーマのメイン領域を切り出す:
  - 優先: `<div role="main"...>` … 対応する閉じまで。
  - 次点: `id="region-main"` を含む要素。
  - 見つからなければ **全文フォールバック**（現行動作を維持し取りこぼしを防ぐ）。
- 締切解析（`extractDeadlineText`→`parseDeadline`）はこのメイン領域テキストに対して実施。
- 候補リンク抽出（`extractLinksFromHtml`）は取りこぼし防止のため**従来どおり全文対象**（コース一覧ページの解析であり、汚染はしない）。
- 効果: 「締切（5/29）」がタイトル汚染を排して実 `期限` で回復。`締切:7月3日` ナビ汚染を構造的に根絶。

### ③ スラッシュ日付対応（develop）

- `parseDeadline` に日本語日付マッチ後のフォールバックとして追加:
  - `YYYY/M/D [HH:MM]`、`M/D [HH:MM]`（年なしは今年を補完、時刻なしは 23:59 補完＝既存挙動と一致）。
- 誤検知抑制:
  - 月 1–12・日 1–31 の妥当性チェック（不正なら不採用）。
  - スラッシュ日付は**締切ラベル近傍**（`extractDeadlineText` が返したラベル起点スライス内）でのみ採用し、本文全体からの拾い読みはしない。②の本文限定と併用で比率・版数（例 `10/10問`）の誤検知を抑える。

### ④ タイトル締切フォールバック（develop）

- 本文（メイン領域）で締切が取れなかった場合**のみ**、`candidate.title` を解析して締切を推定。
  - パターン: `（締切…M月D日…）`／`M/D`／`締め切りM月D日`／`〆`直近の日付 等。曜日のみ（例「金曜日〆」）で日付が無ければ採用しない。
- `Assignment` 型に `deadlineSource: 'field' | 'title' | null` を追加（`null` は締切なし）。本文由来は `'field'`、タイトル由来は `'title'`。
- UI: `deadlineSource === 'title'` の締切は「締切(推定)」と明示（`AssignmentCard` にバッジ/注記）。誤りうる推定である旨をユーザーに伝える。

### 構造・リファクタ（develop）

- 締切解析ロジックを肥大化した `src/background/index.ts` から純粋関数モジュール **`src/background/deadlineParser.ts`** へ切り出す:
  - `extractMainRegion`, `extractDeadlineText`, `parseDeadline`, `toIsoStringFromParts`, `parseDeadlineFromTitle`, ラベル定数群。
  - 副作用なし・単体テスト可能にする。`index.ts` はこれを呼ぶだけにする。

## テスト

- **単体テスト**（`deadlineParser.test.ts`）: 今回の実データ85件から抽出したフィクスチャで回帰。
  - `終了済み` 回復（小試験=6/19 等）／`締切(5/29)` の本文限定回復／スラッシュ表記／タイトルのみ→推定／常時開放小テスト=null 維持／ナビ `締切:7月3日` を採用しないこと。
- **ログイン検知**: `fetch` のリダイレクト各シナリオ（opaqueredirect／`/login/`／未ログイン本文／真のネット障害）をモックして `checkIsLoggedIn` の戻り値を検証。
- 既存テスト（`src/background/index.test.ts` 等）が壊れないこと。

## 非対象（YAGNI）

- Moodle以外のLMS対応。
- カレンダーAPI等、ページ解析以外の締切取得手段。
- ②のDOM完全パース（正規表現ベースの領域抽出で十分。フォールバックありで安全）。
