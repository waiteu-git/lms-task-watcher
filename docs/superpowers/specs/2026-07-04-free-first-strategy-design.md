## 1. 方針転換の要旨

差別化軸を「データの管理場所（同期＝有料）」から「**通知の質と快適装備（自動運転＝有料）**」へ変更する。

- **無料**: モバイルアプリ・時間割・LETUS自動収集・拡張↔アプリ同期まで開放し、ファネルを最大化する
- **有料（¥120/月）**: 「単位を落とさない保険」。見張り番プッシュ・カスタム通知ルール・ウィジェット等の快適装備

### サブスクの位置づけ: 快適性＋開発支援

サブスクは「**快適装備＋開発支援**」を目的とする。必須機能を人質に取る課金ではない。

- **実装ルール**: サブスク関連のUI（アップセル画面・LP・マイページ・ストア説明文等）を実装する際は、必ずこの位置づけを文面に明記する。例: 「サブスクは快適機能のアンロックと、このサービスの開発・運営を支える支援です」
- 無料でも困らない設計（本書2章）とこの文面はセットで機能する — 「支援」の建付けは無料版が十分に使えるからこそ成立する

### 根拠（市場分析 2026-07-04）

- 理科大の学生数は約2万人。ただしChrome拡張という配布形態はスマホ中心の学生の大半に届かず、現行案のままではサブスク到達は初年度1桁〜20人程度と予測
- 収益の最大化変数は転換率ではなく**インストール数**（損益分岐はサブスク3人）。入口を広げる方が期待値が高い
- **LETUSはMoodle公式アプリ非対応**（大学からの案内実績なし）。「スマホにLETUSの課題期限が自動で届く」体験は理科大では唯一無二
- 最大競合のPenmark（理科大対応・無料・時間割＋課題管理）は手動登録ベース。LETUS自動収集が唯一かつ本物の差別化点
- 先例: Twin:te（筑波大）は有志発・1大学特化・無料でキャンパスの大多数に普及。無料ファーストはキャンパス内で商用アプリに勝てる実証済み戦略

## 2. 無料/有料の境界（確定）

### 機能全般

| 機能 | 無料 | サブスク ¥120/月 |
|---|---|---|
| LETUS自動収集（拡張・アプリ） | ✅ | — |
| 課題一覧・手動課題・優先度・メモ | ✅ | — |
| 時間割表示（CLASS連携） | ✅ | — |
| 拡張↔アプリ同期（無料アカウント） | ✅ | — |
| ホーム画面ウィジェット（アプリ） | — | ✅ |
| スヌーズ／後でやる | — | ✅ |
| Discordコミュニティ | — | ✅（実装済み） |
| テーマ | — | ✅（実装済み） |
| 統計・振り返り | — | 据え置き（提出時刻パースの前提調査後） |

### 通知（面＝サーフェスで線を引く）

既存無料機能の後退（ダウングレード）は絶対にしない。無料/有料の線は新しい面（モバイルプッシュ）にのみ引く。

| 通知面 | 無料 | サブスク |
|---|---|---|
| 拡張機能（PC） | 現行の1h/3h/24h警告を**維持** | カスタム通知ルール（科目別しきい値・ミュート） |
| モバイルアプリ | 朝まとめ1日1回（「今日〆切2件、明日1件」） | **見張り番プッシュ**: 未提出のみ24h→6h→1hエスカレーション、提出検知で自動停止。＋カスタム通知ルール |

- 見張り番プッシュが看板有料機能。機能差が体験として一瞬で分かり、「これで救われた」がそのまま口コミになる
- クワイエットアワー（通知しない時間帯）はカスタム通知ルール設計書の判断どおりスコープ外を維持

## 3. 価格・決済（学生のクレカ問題への回答）

- **半期パス ¥720 / 年パス ¥1,200（一回払い）を主軸** — Stripeのコンビニ決済・PayPay（いずれも一回払い対応）が使え、クレカ不要。学期区切りは学生の生活リズムと一致し、解約管理も不要
- 月額 ¥120 はカード・Visaデビット・プリペイド（バンドルカード等）派向けに併存
- 販売はWeb（lms.waiteu.dev、既存マイページ基盤）で行い、アプリは購入状態を反映するだけ → AppleのIAP手数料（15〜30%）を回避。日本のスマホ新法による外部決済誘導の解禁を利用
- 価格はユーザー向けUI（changelog・ロードマップ等）に載せない方針を維持

## 4. v2.0.0 アーキテクチャ: アプリ単体完結

### 基本構成

アプリ単体で全機能が完結する（B案）。拡張機能はオプションの収集源に再定位する。

```
[モバイルアプリ（React Native / Expo）]
  ├── アプリ内WebViewでSSOログイン（LETUS / CLASS）
  ├── アプリ側で収集: LETUS＝課題、CLASS＝時間割
  ├── 判明済み期限からローカル通知を予約（バックグラウンド制約に依存しない）
  └── サーバー同期（無料アカウント）
        ↕
[ラズパイAPIサーバー]
  ├── 収集元（拡張/アプリ）を問わない同一データモデルで受ける
  ├── Expo Pushで見張り番プッシュ・朝まとめ配信
  └── JWT認証・Stripe（既存基盤を再利用）
        ↕
[Chrome拡張機能] = PC派の収集源＋PCダッシュボード（サブ機能）
```

### データソースと認証の原則

| ソース | 取得対象 | 備考 |
|---|---|---|
| LETUS | 課題・期限・提出状態 | 既存スクレイピングロジックのモバイル移植 |
| CLASS（class.admin.tus.ac.jp） | **履修科目・時間割のみ** | 成績等の機微情報を含む管理システムのため、収集範囲を厳格に限定する |

- **認証情報は端末内のみ。サーバーには絶対に送らない**（Orarioが2017年に立命館大から注意喚起を受けた教訓）
- WebView方式ならパスワードはアプリすら触らず、SSO画面に直接入力される
- WebViewのCookie永続化により、セッション切れ時も「ログインボタンをタップ→SSO自動通過」で現行拡張と同等の体験にできる見込み（要実測）
- CLASSのセッション/SSO挙動はLETUSと別物として扱い、個別に実測する

### 課題期限は「事前に分かっている未来の日時」

常時スクレイピングは不要。アプリを開いた時に収集→ローカル通知を予約すれば、iOSのバックグラウンド制約下でも通知は確実に鳴る。サーバープッシュ（見張り番・朝まとめ）はこれを補完する。
