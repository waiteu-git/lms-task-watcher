# デザイン刷新プロンプト（claude design 用）

> 用途：`lms.waiteu.dev` トップ（`landing/index.html`）と `/app`（`landing/app.html`）の2ページを刷新する。
> 下の「本文」をそのまま claude design に貼って使う。冒頭〜末尾まで1本のプロンプト。

---

## ▼ 前提（この縛りで生成させる）

- **本番差し替え可能な自己完結HTML**として出力する。`landing/index.html` と `landing/app.html` をそのまま置き換えられること。単なる見た目モックではない。
- **外部依存ゼロ**：外部CDN・Webフォント・外部JS・外部画像を読み込まない。CSSはインライン、アイコン・イラストはインラインSVG、JSは同一ファイル内の素のJavaScriptのみ。（Cloudflare Pagesの静的配信・CSP無設定でも壊れないため。現行踏襲）
- **既存の機能・SEO資産をすべて保持**（下記「保持必須リスト」）。デザインだけ差し替える。
- **2案を出力**：各ページを「洗練フレッシュ」と「大幅刷新」の2方向で作る（下記「出力指示」）。

---

# 本文（ここから下を claude design に貼る）

あなたはプロダクトデザイナー兼フロントエンド実装者だ。東京理科大学（非公式・学生個人開発）向けの2つのランディングページを刷新する。成果物は**そのまま本番に置ける自己完結の単一HTML**。デザインだけでなく実装まで仕上げること。

## 対象ページ

### 1. `index.html` — PC拡張機能「LETUS Task Watcher」
- 何：LETUS（東京理科大のMoodle系LMS）の課題締切を自動収集し、締切前にデスクトップ通知するChrome / Edge拡張機能。無料。
- ブランド色：**紫**。`--accent:#6366f1` / `--violet:#8b5cf6`、グラデ `linear-gradient(135deg,#6366f1,#8b5cf6)`。この芯は外さない。
- トーン：信頼できる・堅実・「もう課題を見逃さない」。

### 2. `app.html`（URL `/app`）— モバイルアプリ「リタス（Litus）」
- 何：LETUSの課題＋CLASS（履修/時間割/出席）をスマホ単体で扱う iOS / Android アプリ。**近日公開・事前登録受付中**（2026年後期予定）。
- ブランド色：**翠（エメラルド）**。`--accent:#0f9e75` / `--violet:#0b7d63`、グラデ `linear-gradient(135deg,#0f9e75,#0b7d63)`。この芯は外さない。
- トーン：新しい・軽い・持ち歩ける。ローンチ前のワクワク感。
- ロゴマーク（インラインSVG、翠 `#0f9e75`）：稲妻状のパスカット。現行の `viewBox="0 0 48 46"` のパスを流用可。

両ページとも日本語。フォントは `system-ui, -apple-system, "Segoe UI", sans-serif` 系の端末フォントで完結させる（外部フォント禁止）。

## 保持必須リスト（デザインを変えても中身は残す）

**両ページ共通**
- `<head>` のSEO資産一式：`<title>`, `meta description`, `link canonical`, OGP（`og:*`）, Twitter Card（`twitter:*`）, JSON-LD（`application/ld+json`）。`index.html` は `google-site-verification` メタも**削除禁止**。
- 「東京理科大学**非公式**の学生個人プロジェクト」という免責表記（フッター）。
- フッターの相互リンク：プライバシーポリシー / Chrome Web Store / Edge Add-ons / 透明性レポート。
- 2ページ間の相互リンク（index→app の誘導、app→index「PC版はこちら」）。
- Chrome/Edgeストアの実URL（現行のリンク先を維持）。

**`app.html` 固有**
- **事前登録フォーム**をそのまま機能させる：`POST https://api.waiteu.dev/api/waitlist`、body `{ email, source:'app-landing', website }`。
  - honeypotフィールド（`#website`、視覚非表示、botが埋めたら無効）を維持。
  - 同意チェックボックス（プライバシーポリシー同意 + お知らせメール受信同意）必須。未チェックなら送信させない。
  - 送信状態表示（送信中／完了／失敗／ネットワークエラー）を `role="status" aria-live="polite"` で維持。
  - 「お預かりするのはメールアドレスのみ。公開のお知らせ以外に使わない」旨の注記を維持。
- Xフォロー導線（`@yning_y2`）、devlog（`updates.html`）へのリンク。

## 各ページの情報設計（現行の内容を土台に、構成は再設計してよい）

**`index.html`**：ヒーロー（Chrome/Edge追加ボタン）→ 次アップデート予告 → ロードマップ（v1.0.x公開中／v1.1.0申請中／v1.2.0開発中／v2.0.0計画中）→ リタス誘導バナー → できること（6機能）→ 使い方（4ステップ）→ プライバシー → FAQ → アップデート履歴 → サポート → フッター。既存のコピーは流用・洗練してよいが情報は落とさない。

**`app.html`**：ヒーロー（キャッチ＋事前登録フォーム＋スマホUIショーケース）→ CLASS連携ハイライト（目玉）→ できること（「公開時に使える」9件／「順次追加予定」6件）→ 事前登録の説明 → PC版相互リンク → フッター。

## `app.html` の主眼（今回いちばん重要）

### A. サイトを開いたときの演出（エントランスアニメーション）
- ページロード時に要素が立ち上がる演出を入れる（ヒーローの見出し・サブ・フォーム・スマホショーケースが段階的にフェード＋スライドイン、など）。
- **同一ファイル内の素のJSかCSSアニメのみ**で実装。外部ライブラリ禁止。
- `@media (prefers-reduced-motion: reduce)` で動きを無効化する分岐を必ず入れる。
- 演出のモチーフ案：アプリの起動ロゴ（ワードマーク "LITUS" の "LI"＝墨 `#12332a` と "TUS"＝翠 `#0f9e75` が上下から合わさって出現）を、サイトのヒーロー登場に呼応させると世界観が繋がる。任意採用。

### B. アプリUIを「紹介画像的」に見せる（実UI再現ショーケース）
現行は簡易なCSSスマホモック（ロック画面通知・時間割）だけ。これを**実アプリUIをHTML/CSSで忠実再現したショーケース**へ格上げする。スクショ画像は使わず、端末フレーム＋中身をHTML/CSSで組む。少なくとも次の画面を再現し、ヒーローや各セクションに配置する（1枚のヒーロー主役＋複数の小カットでも、横スクロール/積み重ねでもよい）：

1. **時間割（グリッド）** … アプリの目玉。
2. **課題（バケット表示のカード）** … 締切の緊急度が伝わるカード。
3. **出席（カウントダウンリング）** … アプリ独自の見せ場。
4. （任意）**インフォ（CLASS掲示カルーセル）**、**下タブバー**。

再現の正確さのため、**末尾の「実アプリUI仕様」**の配色・ラベル・寸法にできるだけ忠実に作ること。端末フレームはニュートラルな黒/濃紺のベゼル＋角丸。中身は白テーマ（既定）を基本に。

## 出力指示（キモ）

各ページを**2つのデザイン方向**で作る。方向は2ページで一貫した1つのデザイン言語として適用する（＝方向Aのindexと方向Aのappは同じ世界観）。

- **方向A「洗練フレッシュ」**：現行の骨格・情報設計・ブランドを活かしつつ、余白・タイポグラフィ・階層・影・マイクロインタラクション・ショーケースの質感で一段引き上げる安全案。現行を知っている人が「洗練された」と感じる範囲。
- **方向B「大幅刷新」**：レイアウト・ビジュアル言語・演出から作り替える冒険案。大胆なヒーロー、動きのあるショーケース、ダーク/ライト適応、非対称レイアウト、印象的な余白運用など、思い切って提案してよい。ただしブランド色の芯（index=紫 / app=翠）と保持必須リストは死守。

**進め方（推奨）**：まず方向A・Bそれぞれの「app.html ヒーロー＋ショーケース」だけを見せて選ばせ、選ばれた方向で index / app の完全な2ページHTMLを仕上げる、の2段階が効率的。ただし最終的な納品物は「方向A：index.html + app.html」「方向B：index.html + app.html」の計4ファイル（＝各ページ2案）が揃うこと。

各HTMLは：
- 単体で開いて完成している（インラインCSS/JS/SVG、外部依存なし）。
- レスポンシブ（〜380pxのスマホ幅で横スクロールが出ない。ショーケースやグリッドは各自 `overflow-x:auto` の器に入れる）。
- 保持必須リストを全て満たす。

## 画面2：課題（バケット表示）
- ヘッダー：`checkbox-outline`＋「課題」＋右Chip「更新」（`refresh`）。

- 課題カード（角丸18）：
  - 上段：コース名（11px, 薄色, 1行）＋非表示ボタン `eye-off-outline`。
  - タイトル（14px/500, 2行）。
